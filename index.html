Flagship Project

Deterministic Multi-Agent RAG

Not a chatbot wrapper. A LangGraph system where every claim must earn its citation — built on public data so the whole pipeline can be inspected.

Python · LangGraph · FastAPI · pgvector · React
How a question moves through the system query → plan → retrieve → validate → critique → answer
1

Planner

Decomposes the question into sub-queries, picks tools, and sets a retrieval budget. No open-ended wandering.

LangGraph node

2

Retriever

Hybrid search — vector + keyword — over a curated corpus, with reranking and source metadata preserved end-to-end.

pgvector + BM25

3

Validator

Every draft claim is checked against a JSON schema and its cited span. Unsupported claims are rejected, not softened.

Pydantic schema

4

Critic

Adversarial pass: looks for contradictions, stale sources, and prompt-injection in retrieved text before anything ships.

eval-gated

🔍 Citations are enforced, not requested

The answer renderer refuses any sentence without a resolvable source span. If it can't cite it, it doesn't say it.

🧪 Evals run like unit tests

A fixed adversarial set runs on every change: injection attempts, conflicting sources, and unanswerable questions that must trigger an honest “I don't know.”

📋 Everything is traceable

Each run logs the plan, retrieved chunks, validation verdicts, and latency per agent — the same trace you see in the demo below.

What broke — and what changed
  • Conflicting sources: early versions averaged contradictions into a confident wrong answer. Fix: critic flags conflicts and the answer must surface both positions.
  • Citation drift: the model cited the right document but the wrong paragraph. Fix: span-level verification in the validator, not document-level.
  • Injection via retrieved text: a chunk told the model to ignore instructions. Fix: retrieved content is treated as data, never as instructions — and it's in the adversarial set permanently.

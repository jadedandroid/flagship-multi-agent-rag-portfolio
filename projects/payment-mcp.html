PROJECT 03 · MCP TOOL SERVER

Payment setup with compatibility checks before code.

An MCP server for diagnosing a business’s card or crypto checkout requirements, checking local configuration safely, and returning a provider-specific integration scaffold plan.

The initial release generates and validates setup guidance. It does not create merchant resources, accept card data, move funds, or enable live processing.

MCP TOOLS

Small, auditable tool surface

check_payment_compatibility

Checks provider, country and currency formats, payment methods, application stack, server-side boundary, webhook endpoint and signature-verification requirements. Region eligibility still requires confirmation with the provider.

inspect_payment_environment

Checks whether required environment variables are present and whether key prefixes appear consistent with test or live mode. It never returns key values or accepts secrets as tool arguments.

troubleshoot_payment_setup

Maps sanitized diagnostic codes and configuration symptoms to likely causes and next checks. Inputs containing credential-like strings are rejected instead of echoed.

prepare_payment_integration

Returns runnable Stripe hosted-checkout/webhook artifacts for Node or Python, a dependency manifest, and environment template. Coinbase Commerce emits a review gate until its current API and webhook contract can be verified.

write_payment_scaffold

Requires explicit confirmWrite: true, writes only beneath the configured project root to a new payment-integration folder, and refuses overwrites.

STRIPE

Cards and wallets

Designed around server-created Checkout Sessions or PaymentIntents, hosted or Elements-based collection, webhook signature verification, idempotency, and separate sandbox/live credentials. Prefer restricted server keys where supported; never expose secret keys in browser code or chat.

Stripe payment integration docs · API key safety

COINBASE COMMERCE

Crypto checkout

Provider adapter is deliberately capability-gated. Confirm current Coinbase Commerce product availability, supported merchant jurisdictions, currencies, webhook scheme, and account eligibility against Coinbase’s current dashboard and API documentation before enabling an integration.

Never trust a browser redirect as proof of payment; verify signed server-side events and reconcile provider state before fulfilling orders.

CREDENTIALS & CONTROL

Credentials stay outside the model

Supply credentials to the MCP process through a local secret manager or protected environment. The server checks variable presence and prefix only and redacts any credential-shaped input. The writer creates code/config files after explicit confirmation; no MCP tool authenticates to payment providers or performs live provider mutations, transactions, refunds, or payouts. Production execution remains a separate, manually reviewed integration step.
